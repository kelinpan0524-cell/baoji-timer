# 肌群恢复度热力图（点名条目四）

来源：docs/open-source-research-2026-09-25.md「候选与仅作参考」——肌群恢复度热力图（Fitbod 候选）。
引擎实现：`lib/engine/recovery.dart`（纯 Dart）；UI：`lib/ui/recovery_card.dart`（复用解剖热力图 `MuscleBodyView`）。

## 展示位置纪律（红线级）

**恢复度只出现在计划页与统计页，绝不进训练中页。** 训练中屏幕只保留
三要素（当前动作 / 本组目标 / 倒计时），恢复度属于"练后看"的信息，
出现在训练屏就是信息过载（与调研报告「明确不抄的：信息过载训练屏」一致）。

## 计算口径（与代码一致，改动须同步 lib/engine/recovery.dart 头注释）

这是**启发式体感参考，不是生理测量**。参数是经验值，全部为引擎顶部常量。

1. **输入**：近 7 天内全部 `status='done'` 会话的正式组
   （热身组不计；进行中/放弃会话由查询侧排除——见 `lib/db/db.dart`
   头注释「统计过滤纪律」，调研条目 14 的同一套纪律）。
2. **单动作容量**：正式组 Σ(重量×次数)。自重动作在用户填了体重时按
   系数×体重折算（与容量统计同口径 `setVolumeWithBodyweight`）；
   负重量（辅助器械配重）按 0 计。
3. **肌群分摊**：按 `exercise_meta` 映射——主肌群吃该动作容量的 100%，
   每个次肌群各吃 30%（`kSecondaryMuscleShare`，协同受力的经验系数）。
   词表外且库里无映射的动作按「其他」肌群 100% 计。
4. **单场疲劳分**：`min(1, 该肌群本场容量 / 8000kg)`。8000kg
   （`kFatigueRefVolume`）≈ 100kg×8次×10 组的主肌群训练量，一场打满即
   该肌群恢复度归零。
5. **时间衰减**：每场疲劳分乘 `exp(-距该场结束小时数 / 48h)`
   （`kRecoveryTauHours=48`，半衰期约 33 小时）：24h 剩 61%，48h 剩 37%，
   7 天剩约 3%。
6. **恢复度**：`round(100 × (1 - min(1, 各场疲劳分之和)))`，clamp 0-100。
   无任何记录 = 100%（完全恢复）。

### Example

周一晚练胸（卧推 60×8×3 = 1440kg）：

| 时点 | 胸 | 肩/手臂（次肌群 432kg） |
|---|---|---|
| 刚练完 | 82% | 95% |
| 48h 后 | 93% | 98% |

同一天再加一场大容量胸日（如 100×8×10 = 8000kg）→ 胸直接 0%，
之后按 48h 半衰期逐日回血。对应单测：`test/recovery_test.dart`。

## 参数一览

| 常量 | 值 | 含义 |
|---|---|---|
| `kFatigueRefVolume` | 8000 kg | 单场打满一个肌群恢复预算的参考容量 |
| `kRecoveryTauHours` | 48 h | 指数衰减时间常数 |
| `kRecoveryLookbackDays` | 7 天 | 回看窗口（窗外残量 <3% 截断） |
| `kSecondaryMuscleShare` | 0.3 | 次肌群容量分摊系数 |

## 已知边界

- 不区分动作强度/离心肌力/训练年限——同容量下新手与老手疲劳不同，
  本口径一律同权（启发式的取舍，宁可粗而稳定，不做黑盒调参）；
- 睡眠/营养等恢复条件不在建模范围；
- 动作未映射肌群时计入「其他」，热力图上不可见但计入百分比列表；
- 恢复度颜色与容量热力图同向（绿=高），不引入第三种语义色。
